    Stage 7 — Modding toolkit and Interceptor Remastered¶

    Version 0.8.0. Status: planned. The tools that make mods easy, and the proof that a mod can extend a campaign.

    Design: mod structure, Interceptor Remastered.

    Work items¶

    # Item Module
    7.1 --check --campaign <id> grown into the full validator: every definition, reference, condition and text key; JSON report; per-addon checks check
    7.2 Recipes: the generated-asset system (cache keyed by recipe, version and input hash; --build-recipes; build on first use with progress) recipe (new)
    7.3 upscale generator: de-dither, edge-directed ×2 steps, sharpen, alpha re-application, wrap-aware borders recipe::upscale
    7.4 mesh-patch generator: inset, extrude, bevel, cut along UV lines, subdivide, relief from texture, LOD copy; input mesh check recipe::meshpatch
    7.5 recolour and composite generators recipe
    7.6 Viewer: patch hot-reload and before/after comparison; model-set state browser app::viewer
    7.7 interceptor-remastered: parent = interceptor; ×4 textures and ×2 images; the enhanced X-1A Lightning II mesh patch packs/interceptor-remastered
    7.8 default: balance pass, complete encyclopaedia resources/default
    7.9 Modding guide finished: tutorials from "change one number" through "an addon" and "a campaign that extends another" to "a new campaign", built on the default campaign docs

    Mod and cutscene designer (MD4-MD6)¶

    From the mod designer, cutscene designer and game bundling design (decisions D1–D5 made 2026-11-11). The designer is a separate program in the same repository (D5): a second binary, openinterceptor-designer, sharing the engine library, built with macroquad's UI module and the engine renderer (D1), so the build produces two artifacts, the game and the designer.

    # Item Module Requirements
    MD4 Designer application shell: the second binary and build artifact; pack wizard with base selection and folder skeleton; pack tree, schema-driven forms and the YAML view; undo; saving that keeps hand-written files; validation on save; play in the testbed; export as folder or zip designer (new binary) R-MOD-021 – R-MOD-024, R-MOD-028, R-MOD-030
    MD5 Asset import with dependencies (including conversion from original formats by the extractor), external editor launch, live reload, "where used", provenance recording in pack.yaml designer, extract R-MOD-025 – R-MOD-027, R-MOD-029
    MD6 Cutscene Designer: outline, 3D map, preview, timeline with keyframes, cameras and cuts, sounds, captions, scrubbing with snapshots every 2 s designer R-MOD-031, R-MOD-032
    MD8 3D cockpit instrument placement: drag each instrument over the cockpit model; a ray from the eye through the cursor hits a face; the instrument is previewed applied to it (anchor {at, normal, size}), with adjustable size; saved as cockpits.<id>.anchors. Reuses hud::layout::cursor_ray, ray_triangle, anchor_corners and the F12 editor (app/flight.rs edit_layout), which could gain the drag with live preview first designer, hud::layout R-MOD-048, R-MOD-049
    MD9 Example mod: X-COM 3D cockpit, the first test case for the mod tools: an interceptor extension where the modder selects the cockpit images to extract (copied into the mod, provenance recorded), runs Create 3D cockpit, edits in Blender and places the instruments; the generic base cockpit in resources/default (original-free OBJ/MTL and textures from tools/default_assets/); the user's X-COM 3D cockpit example mod in packs/ (original-free geometry, X-COM textures referenced from the original data, requires_original: true) designer, tools/default_assets, packs/ R-MOD-050 – R-MOD-052
    MD10 Single-file models: OBJ/MTL stays fully supported; a .glb reader in-crate as an additional option; .blend sources exported through Blender, run headless when installed (Blender is an optional tool, not a dependency); materials keep their textures formats, model, designer R-MOD-053 – R-MOD-055

    Exit: the remastered campaign plays the whole Interceptor campaign with its generated assets; recipe outputs bit-identical across runs and machines; validator catches every seeded error in a test mod.

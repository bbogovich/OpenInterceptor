# Requirements to replicate the original's strategy logic

Derived from `README.md` (same folder; § numbers refer to it). Each requirement says what the original does,
what the engine does now (app 0.22.0, `packs/interceptor/strategy/*.yaml`, `src/campaign/`), the gap, the
open issue it belongs to, the pack data key that should carry the values (values stay pack data or are
inherited from the player's files; the `default` campaign must keep working with its own values), and how
to test. Confidence follows the README: **V** verified, **D** derived. Ordered by player impact.

Rules for all of them: no value from the exe is hard-coded in Rust; where the exe hard-codes a number, the
`interceptor` pack states it as data with an `@orig` note and its mark; the `default` campaign gets its own
value or the feature off. Every new key is documented on the Modding pages in the same change.

## RQ-S-01 Research prerequisites use the original's tech-id numbering (V) — #32, #25

* **Original:** Prereq / TechRequired ids index the research table in the INI comment's order (0
  ACCUMULATOR_SHIELDS … 73 VCT; 21/32/41 minefields; §4.2).
* **Engine:** `references.yaml` `tech_ids` comes from the third field of the exe's 12-byte table, which is
  shifted by one from id 5 on and wrong for 0–3 (e.g. 57 maps to Sidestep instead of Shade Examination).
  So most prerequisite links and item gates point at the wrong topic.
* **Gap:** regenerate `tech_ids` as position-in-load-order (or from the INI comment list), drop the
  duplicate ALIEN_DRONE at 78 except as an alias, add the three minefield ids.
* **Data:** `tech_ids:` in `packs/interceptor/strategy/references.yaml` (generated by
  `tools/interceptor_strategy.py`; fix the tool, not the YAML).
* **Test:** unit test in the tool (synthetic table); a pack check that no prerequisite has a higher
  `Level` than its topic except the 4 the original itself has; ALIEN_MESSAGE_2's prerequisites read as
  MESSAGE_1 + Structural Component + Type 1 Saucer Examination.

## RQ-S-02 Research rate and completion (V) — #32, #104

* **Original:** per base one topic; every working downlink adds 30/35/40 per hour × elapsed (none while
  jammed); progress is per topic (shared by bases, not lost on switching); done at `FileSize × 1000`;
  +250/500/750 score by Level (§4.1, §2.4). One downlink finishes ~4 topics in 180 days, as the engine does.
* **Engine:** rate expression matches; `switching: lose_progress` does not; no score on completion.
* **Gap:** `research_model.switching: keep` for interceptor; a research score by Level.
* **Data:** `research_model.switching`, new `research_model.score_by_level: [250, 250, 500, 750]` (D: Level 0
  and 1 both 250); `default` keeps its own.
* **Test:** unit tests: two bases on one topic add up; switching keeps progress; Level 3 completion adds
  750 to the month's score. `--strategy-soak 180` with 1 downlink: 3–5 topics; with 3 bases × 3 downlinks
  ≈ 9× faster. #32 can then be closed as "pace matches; prerequisites fixed".

## RQ-S-03 Special (artefact-gated) topics (V) — #25, #23

* **Original:** topics with a Prereq of 127 (26 of them) need an *available* flag, set by recovering the
  artefact; the artefact item must stay in some base's stores or the flag is cleared (§4.2). Nova Bomb has
  five extra prerequisites.
* **Engine:** 127 is dropped from conditions (ids not in `tech_ids` are left out), so these topics are
  open from the start or never.
* **Data:** per topic `requires_item: <item>` (new key; the artefact table at 0x66f768 to be extracted by
  the tool as ids), `requires:` for Nova Bomb's extras.
* **Test:** topic hidden until salvage brings the item; selling the item hides it again.

## RQ-S-04 Monthly accounts from outposts (V) — #29 (closed; reopen or new), #40

* **Original:** income per outpost = `ExchangeRate[difficulty] × Σ working OPP yields × funding`, only for
  outposts older than ~26.6 days; expenses = salaries + `Maintenance × 1000` per module (built or not) +
  hull `MaintCost` per ship; booked on the calendar month change (§2.2).
* **Engine:** `incomes.corporate_funding: 600000 + month_score * 100` (DERIVED); no outposts as objects.
* **Gap:** outposts and OPPs as campaign entities (system, owner, HP, funding, OPP class/richness), the
  yield table, the income formula; `ExchangeRate` read by inheritance.
* **Data:** `economy.exchange_rate_from: original:GameSettings.ini/ExchangeRate` (per level),
  `outposts.yield_table: [[200,400,600,800,800],[300,600,900,1200,1200],[400,700,1000,1300,1600]]` (@orig, V),
  `outposts.start_funding: 0.75`, `outposts.min_age: 26.6d`. Default: its own table or the current flat income.
* **Test:** unit test with a synthetic outpost (3 OPPs, Veteran → 455,625); monthly report lines match.

## RQ-S-05 Outpost evaluation, funding drift, withdrawal and growth (V/D) — #40, #29

* **Original:** per-system monthly scores; `e = X[i] + X/10 − (A[i] + A/5)`; step table
  (−21/−11/−6/−2/0/+2/+6/+11 by thresholds −1000/−501/−251/−1/0/250/500); funding clamp [0, 0.95];
  < 0.03 withdraws (money −1,500, scores ∓1000); X > A adds 1–4/0–2/1 new outposts (cap 3/month, 16 total)
  in the best-scoring system (§2.3).
* **Engine:** one global score; evaluations are rule lists in `economy.yaml` (default) only.
* **Data:** `outposts.evaluation: {pool_weights: [0.1, 0.2], steps: [[-1000,-21],…,[1000,11]], cap: 0.95,
  withdraw_below: 0.03, growth: {per_level: [[1,4],[1,4],[0,2],[1,1],[1,1]], max_per_month: 3, max: 16}}`.
* **Test:** unit tests of each band and of the clamp; a soak where X-COM wins every fight gains outposts.

## RQ-S-06 Scores attach to systems (V/D) — #29, #45

* **Original:** every score goes to the outpost system where it happened, or to a pool; debriefing score =
  Σ counters × `MissionScores[k]`.
* **Engine:** `scores:` with six DERIVED event names; `MissionScores` unread.
* **Gap:** map engine events to `MissionScores` indices (index meanings still **unknown**, README §8).
* **Data:** `scores_from: original:GameSettings.ini/MissionScores` plus `score_events: {<event>: <index>}`.
* **Test:** after the index map is recovered: a scripted battle gives the debriefing total.

## RQ-S-07 Sensor ranges and detection (V) — #23, #22, #99

* **Original:** a base's scan range is set by its sensor module: 2,000 / 4,000 / 6,000 map units
  (⅓ / ⅔ / 1 ly), 0 without one; 6,000 map units = 1 ly (§3.2). Detected alien plans react with
  25 + 10·d % (§6.3).
* **Engine:** `sensor_type1–3: sensor_range 9000/15000/24000` and the hub 3000 (DERIVED) — 3–4× too far.
* **Data:** `base_modules.sensor_type*.effects.sensor_range: 2000/4000/6000` (@orig V),
  `base_types.xcom.sensor_range: 0`; `raids`/strategist `react_on_detect: {per_level: [25,35,45,55,65]}%`.
* **Test:** unit test: contact at 5,000 units seen by a Type3 base, not by Type2; Base Stats shows
  1.00 ly for Type3.

## RQ-S-08 New base price, time and placement (V) — #26 (closed), #101

* **Original:** price 0.75 × (hub + best shield + best downlink + hangar + personnel + cargo + comms + best
  sensor + probe launch + 2 × best beam defence); 29 days; within 130 screen px of a base and 30,000 map
  units of the map centre; ≤ 20 bases (§3.1).
* **Engine:** `cost: 1500000` flat, `build_time: 7d`, `placement: base_distance(system) <= 9000`,
  `max_bases: 8`, a similar template.
* **Data:** `base_types.xcom.cost: template_sum * 0.75` (needs a `template_sum` expression),
  `build_time: 29d`, `placement: base_distance(system) <= <130 px at default zoom, in map units> and
  centre_distance(system) <= 30000`, `max_bases: 20`.
* **Test:** unit test of the price with synthetic module costs and research; soak: a base is ready on day 29.

## RQ-S-09 Manufacturing by outpost technicians (V) — #102, #34

* **Original:** capacity = Σ online outposts × (10 + 10 per working OPP − 10 per broken slot); jobs share
  100 % by their percentage; done at `ProdTime × 60` technician-minutes (§2.5).
* **Engine:** `production_rate` effect of base modules; times from `prod_time`.
* **Data:** `manufacture: {capacity: outpost_technicians, per_outpost: 10, per_opp: 10, unit: 60}`;
  default keeps workshop modules.
* **Test:** unit test: 2 outposts × 2 OPPs = 60 technicians; a 500-hour item at 100 % takes 8.3 h.

## RQ-S-10 Pilot healing and training (V) — #28, #103

* **Original:** +1 health a day, +2 in a medical bay; training every 5 days adds
  `trunc(Int/100 × stat × 0.1 / 6 + 1)` to Accuracy, Flying and Psionics; 5 trainees per Training module
  (§5.1).
* **Engine:** `heal_days: 14`, `survive: 60%`, `training: {gain, cost}` per day (default).
* **Data:** `pilots.heal_per_day: 1`, `pilots.heal_in_medical: 2`, `pilots.training: {every: 5d, formula:
  "int / 100 * stat * 0.1 / 6 + 1", stats: [accuracy, flying, psionics], per_module: 5}`.
* **Test:** unit tests: health 10 → 30 in 10 days in the bay; a 75-Int pilot's Accuracy 60 → 61 in 5 days.

## RQ-S-11 Pilot salary by rank and stats (V) — #28, #29

* **Original:** `(48,000 + rank bonus + Σ stat brackets) / 12` a month (§5.2).
* **Engine:** `salary: 4000` flat (matches a zero-bonus pilot).
* **Data:** `pilots.salary: {base: 4000, rank_bonus: [-1000,-500,0,750,1500], brackets: {accuracy: [[25,-300],…]}}`
  (tables @orig V, extracted to the pack as facts).
* **Test:** unit test: a Commander with 96 Accuracy earns (48,000 + 1,500 + 800 + …)/12.

## RQ-S-12 Alien messages by month and prerequisites (V/D) — #43, #100

* **Original:** messages 1–5 open when their INI prerequisites hold and month value + 1 reaches 3/5/7/9/12
  (derived: Feb/Apr/Jun/Aug/Nov 2067), polled every 5 s real time (§4.3).
* **Engine:** `story.yaml` uses day thresholds 31/59/120/181/273 and per-battle chances (DERIVED).
* **Data:** `events.alien_message_N.when: "month >= M and research_ready(alien_message_N)"`, `M` per message.
* **Test:** soak with prerequisites met early: message 1 appears in February, not January.

## RQ-S-13 Side-mission scheduler (V) — #43

* **Original:** every rand[6, 9) days, the first qualifying of raiders / rogue freighter / pirate rescue /
  Nova hijack / arms dealer / recon by month window and chance (§6.2); fluff missions ≤ 4, every
  ~11.7 d + (6 − d) × 20 h with 1-in-5.
* **Engine:** two DERIVED monthly events (rogue freighter 15 %, Kabron pirates 10 %).
* **Data:** `side_missions: {check_every: [6d, 9d], list: [{id: alien_raiders, months: [3, 8], chance: 10%,
  once: true}, …]}`; `fluff: {max: 4, interval: "1008000 + 72000 * (6 - difficulty)", chance: 20%}`.
* **Test:** seeded soak: raiders never before month 3 or after 8; at most one side mission per check.

## RQ-S-14 Alien treasury and tech level (V/D) — #39, #46

* **Original:** 25-day income from alien outposts (fallback 125,000 × (d + 1)); 6.25-day split by Think.ini
  ratios; 20-hour research spending capped by 20,000 × downlinks / 7; tech level 2/3 at 1.0M…0.5M and
  1.5M…0.9M (§6.1).
* **Engine:** `strategist.aggression` (DERIVED) scales raid chances; no alien economy.
* **Data:** `strategist.economy: {inherit: original:Think.ini/FinancialAI, income_every: 25d, split_every:
  6.25d, spend_every: 20h, fallback: "125000 * (difficulty + 1)", tech_thresholds: {per_level: [[1000000,
  1500000], …]}}`.
* **Test:** unit test: alien tech reaches 2 after the threshold; with Think.ini absent the default plan runs.

## RQ-S-16 Station repair rate (V) — #26, #45

* **Original:** base hull regains `max(5, elapsed_min × 2)` per tick, × 2 with Advanced Damage Control.
* **Engine:** raid-wrecked modules wait for a repair action.
* **Data:** `base_types.xcom.repair: {per_minute: 2, min_step: 5, boost: {advanced_damage_control: 2}}`.
* **Test:** unit test: 600 HP restored in 300 game minutes; 150 with the module.

## RQ-S-17 Calendar-month and weekly reports (V) — #106

* **Original:** monthly accounts and report on the calendar month change; weekly report on
  `time / 7 days` change (§1).
* **Engine:** fixed `MONTH` hours after start (`campaign/mod.rs:263`).
* **Data:** `economy.month: calendar` (default may keep `30d`).
* **Test:** soak from 2067-01-15: first report on 2067-02-01.

## RQ-S-18 Event dialogs drop the clock to the slowest speed (V) — #100, #98

* **Original:** base built, module built, pilot healed, ship damaged and people killed raise a message box;
  its "OK (5 secs)" button selects speed 0 (5 s per s); the plain OK keeps the speed (§1).
* **Engine:** `clock.on_event: 0` drops on every event.
* **Data:** per event `clock: keep | slowest` in the dialog definitions, or two buttons.
* **Test:** manual case (manual-tests.md): each dialog type offers both buttons; the dial follows.

## RQ-S-19 Deliveries by outpost freighter (D) — #46, #37

* **Original:** purchases travel on the seller outpost's freighter (a flight plan, so interceptable);
  arrival checks cargo/personnel/hangar space; ships without a bay are returned with a refund (§2.6).
* **Engine:** `delivery: 72h` (DERIVED) with no route.
* **Settled:** see RQ-S-21…23 (`../unknowns-2026-11.md` §2).
* **Test:** a delivery to a full hangar refunds the ship.

## RQ-S-21 Shipment queue carried by outpost freighters (D) — #137

* **Original:** purchases, transfers, hires and manufacturing output become shipment records (kind,
  id, quantity, load-at side/outpost/base, destination). Paid at order; **no stock or restock**.
  Idle player freighters at an outpost/base load matching records into **100 units** (a ship fills a
  freighter; pilots 1; items size × qty, split when too big), then fly to the destination; 30 min
  unloading and 1 h refuelling per stop (`../unknowns-2026-11.md` §2.1–2.2).
* **Pack key:** `logistics: {freighter_capacity: 100, unload_s: 1800, refuel_s: 3600, stock: none}`.
* **Default:** same rules with the default campaign's freighter hull.
* **Test:** U — loading order, splitting, one ship per trip; arrival after distance ÷ speed.

## RQ-S-22 Strategic speed by mass (D) — #137

* **Original:** map speed (units/s) by ship mass bracket 0.1875 … 0.0375, × 1.15 / × 1.4 for engine
  types 2 / 3; a fleet moves at its slowest ship × a 0–1 factor; mass = hull base + armour + shield +
  missiles + specials (§2.3). Freighters ≈ 1.85 days per light year.
* **Pack key:** hull `mass`, `strategy.speed_by_mass: [[7001, 0.1875], …]`, engine `strategic_factor`.
* **Default:** same table; default hulls get masses.
* **Test:** U — speed for synthetic masses and engines; fleet speed = min.

## RQ-S-23 Alien harassment of plans near alien outposts (D) — #135

* **Original:** every (6 − d) h each X-COM plan in space within 4,000 units of an alien outpost (2,000
  of a base) is attacked with chance 50 + 5d % (§2.4).
* **Pack key:** `aliens.harass: {every_h: "6-d", outpost_radius: 4000, base_radius: 2000, chance: "50+5d"}`.
* **Default:** same for the rival faction.
* **Test:** U — seeded check fires only inside the radius.

## RQ-S-24 Alien raid timing and target choice (D) — #135

* **Original:** next raid after rand[9,12) … [6,9) days by month; target = X-COM base (5/25/40 + 5d %
  by month), else richest-or-random outpost (and possibly one OPP), else mission 3; fleet from the
  nearest alien base with ≥ 3 queued ships, escorts by tech level, speed factor 0.75–0.95 (§3.1–3.3).
* **Pack key:** `aliens.raids: {interval_days_by_month, target_weights, escort_rules}`.
* **Default:** a simpler rival using the same keys.
* **Test:** U — seeded target choice and interval per month.

## RQ-S-25 Alien expansion: outposts and bases (D) — #135

* **Original:** every 25 days 0–3 new alien outposts (by month), every 20 h a possible new alien base
  (< 8 bases and the four triggers), re-found a base when none is left (§3.1).
* **Pack key:** `aliens.expansion: {outposts_every_days: 25, base_check_h: 20, max_bases: 8}`.
* **Default:** same for the rival.
* **Test:** U — seeded counts per month.

## RQ-S-26 Alien base growth: ship queue and modules (D) — #135

* **Original:** each alien base queues one ship every 6 h (class by tech level, research progress,
  class shares and month), builds a module every 40–51 h from a hard-coded tree when funds allow,
  sends a 3-ship scout every 5 days; `Think.ini` Priority/Reserves are unused, DCount only advances a
  stage nothing reads (§3.4).
* **Pack key:** `aliens.base_growth: {queue_every_h: 6, build_every_h: [40, 51], module_order: [...]}`.
* **Default:** same structure with the default rival's modules.
* **Test:** U — seeded queue choice for given shares and tech level.

## RQ-S-27 Mission rating from event counters (D) — #134

* **Original:** rating 1–5 from win/loss, craft destroyed (Σ 2…8: +1 / +0.5 / −0.5), X-COM craft lost
  (−0.5), stations/outposts/OPPs destroyed (+1/+0.5/+0.5), and other terms; thresholds 3 / 1 / −1 / −2
  (`../unknowns-2026-11.md` §4). Score = Σ counter × MissionScores.
* **Pack key:** `debrief.rating: [{counters: [...], rule, value}]`, `mission_scores: {<event>: n}`.
* **Default:** same rules on the engine's events.
* **Test:** U — rating for synthetic counter sets.

## RQ-S-28 Save game: tagged chunks (D) — #137

* **Original:** header (magic, check, version, name) + tagged, versioned chunks per subsystem (§7).
* **Engine:** own format; adopt the shape: a small header and one versioned section per subsystem
  (`player`, `ships`, `pilots`, `clock`, `history`, `shipments`, `universe`, `bases`, `outposts`,
  `ai`, `flight_plans`), each refusing to load on a version mismatch.
* **Test:** U — round trip; a changed section version is rejected with a message.
